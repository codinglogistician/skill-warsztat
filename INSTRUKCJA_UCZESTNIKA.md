# Instrukcja — jak pracujemy na tej sesji

## Pokoje wracają!

Pracujecie **w parach, w pokojach podgrup** — tak jak obiecywał kontrakt z sesji 1:

1. **Pilot** udostępnia ekran i pisze. **Nawigator** czyta plany i wyniki agenta na głos,
   pilnuje karty pracy, proponuje kolejne kroki. Sterowania nie przekazujemy — nawigator
   mówi słowami, co ma się zmienić.
2. **Zamiana ról w połowie warsztatu** — prowadzący ogłosi ją komunikatem do wszystkich pokojów.
3. Po fazach **F2, F3 i F5** pilot wpisuje symbol fazy **na czacie głównym spotkania**
   (nie w czacie pokoju) — to latarnia dla prowadzącego.
4. Utknęliście? Napiszcie „pomoc" na czacie głównym — prowadzący krąży po pokojach,
   przyjdzie do Was.

## Zasada z sesji 2, która obowiązuje nadal

Po każdej zmianie agenta nawigator mówi na głos, **co dokładnie się zmieniło**.
Nie „ok, działa" — tylko „utworzył plik SKILL.md z sekcją opisu i trzema krokami".

## Start (pilot, w VS Code)

1. Otwórz VS Code → **Terminal → New Terminal** (terminal otwiera się na dole okna).
2. W terminalu, w folderze na projekty kursu:

```bash
git clone <ADRES_Z_CZATU>
```

3. **File → Open Folder…** → wybierz sklonowany folder `skill-warsztat`.
   Od tej chwili eksplorator po lewej pokazuje pliki projektu, a terminal działa w jego wnętrzu.
4. W terminalu uruchom agenta: `claude` — i otwórz `KARTA_PRACY.md` w edytorze (jeden klik
   w eksploratorze). Idźcie faza po fazie.

## Jeśli coś nie działa

Dwie minuty walki — potem „pomoc" na czacie głównym. Awaryjnie: całość działa też
w samym terminalu, bez VS Code, dokładnie jak na sesji 2.
